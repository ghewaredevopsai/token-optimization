Everything so far was about how you ask. This tier is about the calls your software makes on your behalf, where the cheapest token is the one no model ever sees.

The ladder

Cheapest to do at the bottom. Most people start at the top.

The two widest bars cost nothing and need nobody's approval. The narrowest one is the one every cost conversation opens with, because changing the model feels like a decision and starting a new chat feels like housekeeping.

Worth stating plainly: "set max_tokens" is on almost every cost checklist on the internet and it is the second-least effective thing here, because it caps the 0.8% of traffic that is output. It is still worth setting - as a runaway guard, not as a saving.

The bottom rung

Is the answer derivable from data you already hold?

A prompt somebody runs per consignment

# prompts/summarise-exceptions.md
Read the exceptions report and group
the consignments by what is wrong with
them, say how many of each, and suggest
what to do about each group.

~1,900 est. tokens per run, and three runs give three different groupings.

The same answer, in Python

from collections import Counter
counts = Counter(
    code for row in rows
    for code in row["codes"])

0 tokens. Same result every time.

The token column is not the argument — the variance column is. Counting exception codes is not a judgement call, and a model was being paid to be non-deterministic about arithmetic. Keep the model for the part that needs judgement: what to do about the group.
Lab 4 now: replace that prompt with about twenty-five lines of standard library. Record tokens before and after, wall time, and — the column nobody expects — how many of three runs gave identical output.

This is the tier's whole argument and it is deliberately last, because a room that hears it first decides the module is anti-AI. By here they have measured enough to hear it as what it is: use the expensive, non-deterministic tool for the part that is actually a judgement.
