What is on the meter

Metered: chat, agent mode, code review, the CLI, the cloud agent.

Not metered on a paid plan: completions and next edit suggestions.

Auto model selection takes 10% off.

At zero, the default is backwards from what you expect. On an individual plan extra usage stays off until you turn it on and set a budget. In an organisation it is on by default, so the bill keeps growing until an admin caps it.
Output is the expensive token. Input is where the tokens are. Everything in this module follows from those two facts being about different things.

Say the organisation default twice. It is the single most expensive line on this slide and the one people assume is the other way round, because their personal experience is of an individual plan that simply stops.

Measured · one workshop day

42.7 million tokens, and 99% of them were input

3,892 requests

across 27 active people — about 11,000 tokens per request.

Shorter answers save ~5%

"Be concise" is aimed at 0.8% of the traffic. It is not a cost lever.

46% in one hour

Nearly half the day's bill inside a single afternoon hour.

Why input dominates: every agent turn re-sends the system prompt, the instruction files, the tool definitions, the conversation so far and every file it has read. The answer is short. The context behind it goes again, in full, every turn. Cached input bills at a tenth — that is the discount a stable context earns.

Source: the token and request counters of the workshop's model gateway over one full delivery day, across every participant key. The workshop ran on an open-weight model, so the absolute spend is not a Copilot invoice and is never quoted as one. The 99.2 / 128:1 split is the transferable part, and it is a property of how agents work rather than of which model was behind them.

Guardrails before the pilot, not after it. Individual plans: turn extra usage on deliberately and set a budget. Organisations: it is already on — set user and cost-centre budgets on day one. And know what you can see: usage views are aggregated and delayed, never per request.
